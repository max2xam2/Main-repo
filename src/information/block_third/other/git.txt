1)Что такое git?
Git - это распределенная система управления версиями проекта с открытым исходным кодом. Git хранит всю историю изменений
файлов в проекте, дает создавать новые ветки для разработки новых функций и сливать их в основную ветку без потери
данных. Под распределенностью системы понимаем то, что каждый разработчик имеет локальную копию репозитория со всей
его историей, что позволяет работать безопасно.

2)Какие еще есть системы контроля версий?
SVN - централизованная система контроля версия, то есть существует один центральный репозиторий, откуда все разработчики
копируют копии проекта и потом обратно комитят изменения на сервер. Так как модель централизована, то есть возможность
строго контролировать доступ к исходному коду, также отслеживает не только изменения файлов, но и изменения в структурах
папок. Но требует постоянного соединения с сервером для большинства операция и по сравнению с git, предоставляет меньше
гибкости при работе с ветками. Так как имеет централизованный контроль версий, что означает, что центральный сервер
будет иметь как новые, так и исходные файлы
Bazaar - распределенная система контроля версий, каждый разработчик может иметь полный локальный репозиторий и работать
автономно, а потом синхронизировать изменения с другими. К плюсам можно отнести то, что можем использовать как с общим
центральным сервером, так и распределенно(у каждого есть локальная копия)

3)Возможности git?
Хранение истории изменений: Git позволяет отслеживать изменения файлов в проекте с момента создания репозитория, также
можно отслеживать кто, когда и какие изменение сделал
Ветвление и слияние: можем работать параллельно над несколькими изменениями без риска сломать основную ветку, слияние
веток позволяет объединить работу нескольких разработчиков
Инструменты для интеграции и автоматизации: легко интегрируется с CI/CD, системами тестирования

4)Преимущества и ограничения git
Преимущества: распределенная система - каждый разработчик имеют локальную копию репозитория, можем работать с проектом
офлайн и позже синхронизировать все изменения; быстрое создание и удаление веток, что позволяет безопасно работать над
новыми функциями и безопасно сливать все изменения; хранит всю историю изменений в проекте и исключает потерю данных,
можем откатиться к любой версии
Недостатки: сложность на начальном этапе, так как есть много необычных концепций; плохо работает с большими бинарными
файлами, так как git оптимизирован для текстовых файлов и для работы с бинарниками нужен Git LFS; могут возникать
конфликты при работе несколькими разработчиками во время merge и нужно будет разрешать эти конфликты

5)Что такое репозиторий и как его использовать?
Репозиторий - хранилище, где хранятся все файлы проекта, история изменений, ветки, коммиты и теги. Репозиторий позволяет
хранить код проекта, отслеживать все изменения и возвращаться к предыдущим версиям. Если хранить репозиторий в
GitHub/Gitlab, то наш репозиторий хранится на сервере, что позволяет подключаться нескольким разработчикам к нему

6)Что такое коммит, ветка, пуш, клон и форк репозитория?
commit - сохранение текущих изменений в репозиторий, фиксирует текущее состояние и добавляет описание изменения, так как
каждый commit сохраняется в истории изменений, то мы можем возвращаться к предыдущим версиям
branch(ветка) - отдельная линия разработки, которая указывает на один конкретный commit; используются чтобы каждый
разработчик мог работать над разработкой своей функции и не ломать основной код, после завершения работы изменения
объединяются с основной веткой
push - это отправка локальных изменений из компьютера разработчика в удалённый репозиторий(GitHub/Gitlab)
clone - это утилита git, которая нацелена на существующий репозиторий и создает его клон для целевого репозитория.
Исходный репозиторий может храниться в локальной файловой системе или в поддерживаемых протоколах, доступных удаленной
машиной. Это полноценный репозиторий Git, имеющий свою собственную историю, управляющий собственными файлами и
поставляемый с полностью изолированной средой от исходного репозитория. Процесс клонирования создает удаленное
соединение, которое указывает на исходное репо.
fork - создание копии стороннего репозитория в своем аккаунте, далее можем отправлять pr владельцу проекта
pull request(pr) - запрос на внесение изменений в код. После того как разработчик заканчивает работу над новой функцией
или исправлениями, разработчик отправляет PR, чтобы запросить внесение изменений своей ветки с основной или веткой
другого разработчика, в PR видны все изменения, которые были добавлены разработчиком, остальные разработчики могут
смотреть PR, предлагать свои изменения, оставлять комментарии и после одобрения всех изменений они могут быть слиты
с другой веткой.

7)Основные команды для работы?
git init - создание пустого репозитория в папке, в которой находимся
git remote add name <URL> - подключаем удаленный репозиторий
git clone URL - клонирует удаленный репозиторий на наш компьютер
git status - показывает измененные файлы
git diff / git diff file - показывает, что именно изменилось
git add file / git add . - добавить конкретный файл или все файлы
git restore --staged file.txt - удалить конкретный файл
git commit -m "line" - сохраняем все изменения
git log - метаданные коммита
git push - пушим все добавленные файлы/изменения
git pull branch - получаем изменения в ветке
git branch name - создание новой ветки
git checkout name - переключение на ветку name
git checkout -b name - создание ветки name и переключение на нее
git branch - создание веток
Также можем создать новую от какой-то другой ветки с тем же состоянием
git switch branch //переключаемся на эту ветку
git switch -c feature-header //создаем новую ветку от branch с тем же состоянием
git restore file.txt - изменили файл, но не закомитили
git revert a3f5c2d9 - откатить коммит, который уже отправлен на сервер по ID коммита, который можем получить с помощью
git log будет создан новый commit, который отменяет изменения
git reset --hard HEAD~1 - откат всего репозиторий на один коммит назад и удаление всех изменений

Также
ls - показывает список файлов и папок в текущей директории
pwd - полный путь текущей директории
rm file - удаление файла
rm -r folder - удаление папки с ее содержимым
cd name - перейти в папку
cd .. - перейти на уровень выше
cd ~ - перейти в домашнюю директорию

8)GitHub и GitLab?
GitHub\GitLab - это веб-платформа для работы с репозиторием системы контроля версий Git. Они позволяют хранить исходный
код проектов, управлять версиями, отслеживать изменения и работать над кодом совместно с другими разработчиками.
Также они предоставляют инструменты для code review (pull request / merge request), управления задачами (issues),
настройки CI/CD для автоматической сборки и тестирования проекта, а также контроля доступа к репозиториям.

9)Что такое конфликт и как его можно разрешить?
Обычно конфликты возникают, когда два человека изменяют одни и те же строки в файле или один разработчик удаляет файл,
который в это время изменяет другой разработчик. В таких случаях Git не может автоматически определить, какое изменение
является правильным. Конфликты затрагивают только того разработчика, который выполняет слияние, остальная часть команды
о конфликте не знает. Git помечает файл как конфликтующий и останавливает процесс слияния. В этом случае ответственность
за разрешение конфликта несут разработчики. Git покажет нам две конфликтующие версии и разработчик должен вручную
выбрать правильную версию

ваши изменения
=======

>>>>>>> branch-name

ветке
далее мы должны либо оставить свою версию, либо другую, либо объединить их

10)Разница между локальным и удаленным репозиторием?
Локальный репозиторий - хранится на собственном компьютере и работаем с ним напрямую, создаем коммиты, ветки и изменяем
файлы
Удаленный - хранится на сервере или платформе, например на GitHub для совместной работы, нужен для совместной работы,
синхронизации работы команды и хранения кода
